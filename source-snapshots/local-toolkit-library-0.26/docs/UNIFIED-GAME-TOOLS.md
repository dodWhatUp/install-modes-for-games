## Version-independent data

The [installed preservation audit](GAME-TOOL-CONNECTIONS.md#2026-10-12--installed-profile-and-file-preservation-audit)
confirmed that previous user data remain at their original locations and are
read by the latest installation. No active import was needed. All 29 native
profiles, 68 Studio fields and 97 durable Hub files remained exact; the F7
picture matched its historical recovery bytes. A new private 134-file recovery
export includes independent MIC settings/canvases and referenced images, with
every entry restored/hash-verified in a separate evidence folder. This verifies
new-copy recovery, not native profile activation or restored app behavior.

**User data** has three explicit, vertically scrollable workspaces: export selected files, inspect/restore
a private backup, and inspect/migrate a shared-envelope JSON record. Enter a
source/portable name, add only the desired files, enter a new destination and
preview before creating the copy. Export packages are private recovery artifacts,
not public authored-source releases. They include selected source locators and
exact hashes; no automatic discovery, upload or active-profile import occurs.

`GameToolUserData` separates `schema_version`, `data_version` and producer app
version. Stable IDs, links, provenance and unknown fields survive the supported
additive v1→v2 envelope migration. Inspection automatically prepares that known
conversion, but only an explicit confirmation writes a **new** migrated file.
Native INI/device profiles and earlier recovery exports are opaque byte-preserved
inputs, not guessed conversions. Existing native consumers remain their owners.

Restore verifies the ZIP and reviewed digest again, then creates only a NEW
directory with unchanged files under `data/`, a manifest and receipt. It never
merges into current data or activates imported settings. Interrupted copies
retain an incomplete marker. Unknown future format versions are read-only and
block restore/migration. Hashes do not authenticate a publisher or grant action
authority. Schema-1 journals remain readable across module-version changes,
with original writer labels/hash chains intact and unknown schemas refused.

This is cloud-ready manual packaging, not a cloud synchronization engine. A
future connector needs explicit destination/credentials, conflict previews,
revision/hash-based merging and private/public separation. It must not silently
overwrite a newer profile or use imported data as permission to run an action.

This optional front door embeds the preserved native AHK Studio in the Hub’s
**Studio** workspace. It is one visible interface, not one process: Python/Tk
hosts Hub pages; AHK retains picture buttons, rich previews/atlas tools, MIC,
key display, original tray/shortcuts and optional Game Input. The nine existing
Hub tabs remain. Original Ctrl+1–8 shortcuts remain; Studio/Updates do not forward
remembered Tools/Reports actions. Native Studio fields and editing operations

The Studio 2.2 groups preview is the source foundation. `2.2.0-unified.1` adds only

## Installation and updates

Use a trusted curated GameTools source ZIP and its separately known SHA-256.
`Install-UnifiedTools.py` requires a new named installation root, explicit existing
Studio/settings/data/runtime paths and a fresh six-file expected Studio hash map.
It refuses active known games/capture/benchmark owners and all AHK hosts, rechecks
source drift, stages a bounded source inventory and replaces six named authored
Studio source files plus its own stable launcher. The old standalone launcher and all user data stay in place.
The initial private full checkpoint is separate from public source bundles.

The stable `Start-UnifiedTools.pyw` resolves `install.json` to a verified immutable
`versions/` directory. Open this launcher for the unified interface. A cooperative
per-install Windows mutex prevents a second unified instance. A source-folder
ownership lease also guards cooperating installs sharing the same Studio files.
Neither is a global desktop/input lock; unrelated chats and legacy launchers do
not honor them. Interrupted leases require inspection, never guessed removal.

In **Updates**, enter/select a local ZIP and expected hash, then **Inspect package**.
Inspect is read-only. **Update** is explicit and confirmed; it closes only this
Hub’s native child normally, checks relevant owners/source drift again, creates
private recovery source/INI/bootstrap copies, stages an immutable version and
rechecks the complete source inventory immediately before atomically committing
the strict version pointer last. **Restart unified app** uses the same stable
launcher after the host's normal session/overlay/Studio cleanup. No uninstall, automatic download, registry service, input socket,
privilege escalation or settings reset is needed. Roll back a previous unified
version explicitly through the same guarded path; the original pre-unification
Studio uses its separate initial recovery backup.

Hashes establish integrity/source consistency, not publisher authentication.
Select only trusted authored packages. Version directories and manifests are not
signed. Local tampering with both manifest and code is outside this integrity
model. Failed/partial stages are retained for inspection. A crashed update lock
blocks launch/update: inspect private `recovery/*/transaction.json`, installed
hashes and pointer before removing it. Never replay arbitrary recovered commands.
Conditional failure recovery restores only unchanged bytes written by that
transaction; conflicting user edits are retained. Acknowledged source and pointer
writes are flushed/fsynced; whole-system/power-loss durability is not guaranteed.

## Desktop acceptance and deferred work

Offline fixture tests cover verified ZIPs, tamper/traversal/duplicate rejection,
version/hash drift, active-owner blocking, scoped install/update, pointer-based
launch, conditional rollback and interrupted/conflicting swaps. Tk fixture
controls are isolated; they do not establish real desktop or game acceptance.
Record actual installed native docking, all retained pages, scroll/preview,
Game Input Off, normal stop/restart/cleanup and protected before/after hashes
separately in the private task receipt and connection history.

This interface does **not** implement/resume games, benchmarks, recording, mod
installation runners, extended in-game input acceptance or MFG/FrameWarp tests.
Effective-FG and memory comparison gates, saved-report evidence and mock-health
limitations remain unchanged. Close the unified interface to stop its owned
Studio engine normally; independent native Azeron software remains untouched.

Design: goal-oriented navigation, retained original tabs and contextual explicit controls, optional details and
scrolling preserve the existing design/features without redesigning other apps.
AHK’s documented external-parent limitations informed attach-after-creation;
cross-process DPI/layout requires actual desktop verification. Sources:
[AHK Gui Parent](https://doggy8088.github.io/AutoHotkeyDocs/docs/lib/Gui.htm#Parent),
[Microsoft SetParent](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setparent).
