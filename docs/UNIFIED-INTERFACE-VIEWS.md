# Unified Game Tools: Existing and New interfaces

The main Hub offers an **Interface: Existing / New** selector. Existing remains
the default until the user selects New. Selection is saved independently from
game profiles, native bindings, Overlay maps and appearance preferences.

Both views run in the same Hub window. Switching retains the original widgets,
Studio/runtime owners and each interface's pending drafts. It does not apply a
mod profile, change a game binding, publish an Overlay or start input/capture.
The new view reuses the original Mod Controls service, game installation
identities, applied files, profile owner, recovery and ownership checks.
New saved profiles are shared; earlier parallel-preview profiles remain readable.

**All tools** lists every original page dynamically, including later extensions.
Selecting one returns to Existing and opens that page without rebuilding it.
Disabled pages stay disabled. Studio, Azeron planning, Overlay, runtime profiles
when installed, AI requests, updates and other original pages keep their owners.

The New view retains grouped controls, floating settings, independent window
pinning, local scoped search, Show/Hide sections, file refresh, locations and
chosen-program handoffs. Hiding a control does not disable its feature. Search
reveals a control; it never invokes Apply, export or a toggle. Manager preparation
does not establish a tested native import/deployment. Unsupported game features
remain unsupported, and the experimental Shadow of War DLAA/NR state is unchanged.

Default widget styles, current geometry, the Hub close handler and existing
keyboard bindings are preserved. Embedded New styling uses its own style names;
returning to Existing restores its shortcut bindings and original pin state.
A missing or failed optional New view leaves Existing available.

The main **Show APP LAUNCHER** action locates the included launcher folder.
**Unified Game Tools APP LAUNCHER** opens the installed version; it is not an
installer. Legacy entry points and the independent UI preview remain available.
The preview's private layout/drafts can be retained through an explicit local
review-root binding. The installed view preference contains no game commands.

Source reconciliation keeps the canonical Mod Controls lineage and the Azeron
workflow lineage. Component packaging starts from the exact verified installed
source and preserves every unrelated payload, including newer runtime profiles,
Overlay diagnostics, planner, Studio and updater files. File verification, GUI
acceptance and physical game/Overlay acceptance are recorded separately.
