## What remains useful

- **Respect the sparse comfort constraint.** The decision review found 24
  identical BASIC keyboard outputs; only BASIC #30 differs between CORE5 and
  SPARSE6. Only three of the 32 inherited demands distinguish modeled route
  outcomes. Do not choose a family by total passing cases or assume a different
  combat base. The user subsequently selected SPARSE6; do not request that choice
  again or import both alternatives. Preserve the nine blank finger positions.
  The [decision brief](https://github.com/dodWhatUp/install-modes-for-games/blob/f7511d43956c20ab4280bbcf5e2d0744dd04adf1/research_outputs/input-controls/azeron-keybinds/r8/design-review/CODEX_DECISION_BRIEF.md)
  retains the full tradeoffs and experiment groups.
- **Use the updated owner-held source plus later fixes.** The precedence
  clarification is pinned in the
  [R8 handoff](https://github.com/dodWhatUp/install-modes-for-games/blob/f7511d43956c20ab4280bbcf5e2d0744dd04adf1/research_outputs/input-controls/azeron-keybinds/r8/preflight/READY_FOR_CODEX.md).
  Do not regenerate profiles merely for a revision or replace the rich Atlas
  master with this summary.
- **Separate configuration, output and task evidence.** PoE2's saved input-mode
  indicators conflict, and its modifier token remains undecoded; a skill slot is
  not the equipped skill. Cyberpunk settings/XML are context-dependent candidates,
  not a verified merged runtime preset. Parser recognition or a running remapper
  does not prove the effective input path. Keep unresolved action labels Unknown.
- **Native import can change identity.** The installed app rejected standalone
  candidate JSON; a supported native-format package was prepared. Import assigned
  new IDs while leaving ten old layer targets, which were repaired through the
  native UI. The historical review verified six added SPARSE6 profiles and all
  23 prior profile files unchanged. Use fresh installed IDs and reciprocal links,
  not candidate IDs. Auxiliary native normalizations were reviewed separately,
  without weakening the conservative comparison.
- **Keep display ownership separate from input ownership.** Foreground game
  selection chooses action labels/assets, not native mappings. Preserve geometry,
  blank masks, reserved/unassigned #19 and the unchanged stick configuration.
  Passive held Peek and interactive pinned Explore are different modes. Do not
  invent an overlay trigger or infer a native bank from an ordinary keyboard key.
- **The UI preference is already integrated.** The chat established the
  [compact design foundation](UI-AND-CONTENT-DESIGN.md): editable selection/search/
  entry where suitable, contextual controls, discoverable Show/Hide and optional
  detail. Its local reusable skill and instruction routing exist. No duplicate
  preference system or unrelated UI migration is required.

## Reusable technical lessons

The [Windows read receipt](https://github.com/dodWhatUp/install-modes-for-games/blob/9e438fd2887e1347a2c507ca799aefa04565bfd1/docs/AZERON-R8-WINDOWS-READ-2026-10-11.md)
records two bounded fixes: Windows Python 3.12 path/handle timestamp semantics
caused a false stability rejection, and cp1252 reading of UTF-8 JavaScript broke
the Atlas builder. Use the corrected reader and explicit UTF-8; retain independent
identity/stability/reparse checks rather than disabling safety guards. A bounded
aggregate exceeded the checker limit, so the supported ZIP layout was used;
the limit was not raised. These results are historical, version-specific evidence.

These findings refine existing checklist items **GT-051–GT-053 and GT-059**;
they are not a new task queue. Remaining physical/effective-game/foreground-game
acceptance and deeper usability work stay pending. Historical instructions do
not resume those experiments or authorize another import.
