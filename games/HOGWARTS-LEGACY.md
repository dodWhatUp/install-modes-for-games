## Tested environment

- Windows 11
- NVIDIA GeForce RTX 5070 Ti, driver 616.56
- 3840×2160 borderless
- Hogwarts Legacy build reported by OptiScaler as `1.0.1569535`
- OptiScaler development build `10.0.0-dev (433cc11)` dated 2026-09-01
- Ultra Plus installed through its UE4SS-based layout

The tested executable directory was:

```text
<Steam>\steamapps\common\Hogwarts Legacy\Phoenix\Binaries\Win64
```

Install beside the executable in that directory, not beside the small root launcher.

## Verified final separation of responsibilities

- The game used native DLSS Balanced.
- The game configuration requested native NVIDIA DLSSG with two interpolated frames (`X3`).
- OptiScaler loaded as `dxgi.dll`, detected Hogwarts Legacy and native DLSS/Streamline libraries, and loaded its game patch successfully.
- OptiScaler frame generation was disabled (`nofg`) so it did not fight the native Streamline path.
- OptiScaler's experimental DLSS neural-rendering pass was enabled.
- Overlay blocking was enabled for stability.

This is the key lesson: use native game MFG and OptiScaler neural rendering as separate layers. Do not have both the game and OptiScaler create frame-generation output.

## Installation workflow

1. Launch the stock game once and save a copy of `%LOCALAPPDATA%\Hogwarts Legacy\Saved\Config\WindowsNoEditor`.
2. Back up `Phoenix\Binaries\Win64` and the stock NVIDIA plugin DLL versions.
3. If using Ultra Plus, install it using the current Ultra Plus Mod Manager instructions. Launch-test it before installing OptiScaler.
4. Extract the current OptiScaler release beside `HogwartsLegacy.exe` and run its setup script.
5. Select the proxy recommended by the current OptiScaler compatibility entry. The tested path used `dxgi.dll`.
6. Supply any neural-rendering model/runtime only through the upstream instructions. Do not overwrite or rename the game's Ray Reconstruction DLL.
7. Start from [the conservative example](../examples/hogwarts-legacy/OptiScaler-conservative.ini).
8. In game, select DLSS and enable native frame generation. Test before adding model-preset overrides or dynamic resolution.

## Conservative tested values

```ini
[Upscalers]
Dx12Upscaler=dlss

[FrameGen]
Enabled=false
FGInput=nofg
FGOutput=nofg

[DlssNr]
Enabled=true
AutoCapture=false

[Hotfix]
DisableOverlays=true
```

The local test briefly used `AutoCapture=true`, but that creates large diagnostic captures. It is disabled in the public example.

## Ultra Plus and dynamic resolution

The recorded Ultra Plus profile kept its auto-apply feature off and used a conservative `rtao` lighting mode. The user configuration also contained:

```ini
r.DynamicRes.OperationMode=2
r.DynamicRes.FrameTimeBudget=33.333
r.DynamicRes.MinScreenPercentage=50
r.DynamicRes.MaxScreenPercentage=100
r.DynamicRes.DynamicFrameTime=0
r.DynamicRes.TargetedGPUHeadRoomPercentage=10
```

This targets roughly 30 rendered FPS before frame generation. It is not a universal best setting. Set the frame-time budget from the rendered-frame target, not the displayed generated-frame target.

## What worked

The final OptiScaler log proved:

- correct game and executable detection;
- `dxgi.dll` proxy mode;
- native DLSS, DLSSD, and DLSSG library discovery;
- successful OptiPatcher game patch;
- correct NVIDIA GPU selection;
- more than 10,000 Streamline frames processed before normal cleanup.

See [the sanitized evidence](../evidence/HOGWARTS-LEGACY.txt).

## What did not work reliably

### Forced Dynamic MFG plus native frame generation

Experimental profiles used:

```ini
[FrameGen]
FGInput=dlssg
FGOutput=dlssg

[DLSSG]
ForceDMFG=true
FramerateTargetDMFG=144.0
```

This added another controller around a game that already had native Streamline/DLSSG. Startup and overlay crashes made results inconsistent. The final stable profile disabled OptiScaler FG and kept native game FG.

### Forcing model-preset numbers

Profiles also forced SR preset `12` and RR preset `6`. These numeric values are build-specific and were not proven to improve the final result. Prefer NVIDIA App's supported per-game model override or the current OptiScaler UI labels instead of copying unexplained numeric presets.

### Changing everything at once

Ultra Plus, Engine.ini dynamic resolution, model overrides, forced MFG, and neural rendering were initially changed in the same period. That made every crash ambiguous. Re-testing one layer at a time isolated the stable configuration.

## Rollback

1. Close the game and launcher.
2. Run the OptiScaler remover generated by its setup script.
3. Remove only leftover OptiScaler proxy/support files listed by that installer.
4. Restore `WindowsNoEditor` settings or let the game regenerate them.
5. Use Ultra Plus Mod Manager to remove/update Ultra Plus; do not delete unrelated UE4SS mods.
6. Verify game files and launch stock once.
