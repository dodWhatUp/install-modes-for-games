# Setup, transfer and upgrades

Use a SHA256-verified `isolated-lab-source-<version>-*.zip` and the independently supplied hash. The archive includes the controller, guest providers, dependency lock, setup scripts, skill and operating records. It excludes machine bindings, keys, VM disks, personal configuration, credentials and raw evidence. Do not copy a whole Codex configuration or another computer's key.

Current host adapter: Windows x64, Python 3.11+, Windows OpenSSH Client. Linux is the guest OS; a Linux/macOS host needs a new adapter and acceptance. Use a dedicated private lab outside OneDrive/Git. The installer detects paths and binds this skill locally; no VM starts on installation.

The resolver can report a retained source bundle and expected hash when a skill-only update preserves an older active runtime. Read the portability guide from that verified bundle if it is not yet in the runtime source. `portable_setup.py bind-skill --bundle <zip> --sha256 <hash> --lab-root <existing-root>` updates this workflow/binding without guest lifecycle or running-source changes. A first adoption of an inspected owned skill requires `--adopt-existing`.

Read `docs/ISOLATED-LAB-PORTABILITY.md` from the verified bundle for the complete selected-host procedure. Start with `portable_setup.py preflight --lab-root <selected-root>`, then `install --bundle <zip> --sha256 <received-hash> --lab-root <selected-root>`. `verify` checks installed source. `prepare_portable_linux.py --lab-root <root>` downloads exact locked dependencies, creates a fresh guest key, finds available loopback ports and prepares a new disk. A changed/unavailable dependency is a diagnosis boundary, not a reason to substitute latest versions. Existing configuration is preserved.

After explicit requested provisioning: start/wait-ready, deploy the helper, install browser/AT-SPI providers inside the guest, run cold/native/MCP acceptance and stop cleanly. Record machine-local acceptance and resolved package versions. Register `isolatedLab` through `configure_mcp.py`; use `accept_codex_client.py` to confirm client discovery. Verify the active chat's actual tool catalog separately. No automatic account-wide synchronization or guaranteed implicit skill choice is asserted; `$isolated-lab` is the reliable explicit entry point.

For an upgrade, inspect stopped guests and take a stopped-disk checkpoint before changing guest software. The source installer requires `--upgrade` for a different version, preserves replaced source and rejects locally edited installed files. Review the recorded transaction for conditional recovery. Do not overwrite later edits, restart unrelated chats, close another workflow's sessions or silently upgrade dependencies. Application-specific setup belongs in task-selected project manifests and guest scripts, with its own installation/readback/acceptance.
